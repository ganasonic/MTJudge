# AI動画重ね合わせ比較（Simulcam方式）設計・調査

調査日: 2026-11-10 / 状態: 実装前の仕様・設計案。静的なソース調査のみ。

## 1. 目的と変更禁止事項

同じモーグルコースをほぼ同じ撮影位置から手持ち撮影した2動画を、背景のコブ・コース境界を基準に位置合わせし、ユーザーが選んだ良い滑りと悪い滑りを重ねて比較する。滑りの良否をAIが採点する機能ではない。

要求仕様:

- OpenCV ORB/SIFT・RANSAC・Homographyによる背景位置合わせ。
- オプティカルフローによるパン・ズーム・手ぶれ追跡。
- Vision/Core MLによる選手検出と背景特徴点からの除外。
- Metalによる半透明合成と選手切り抜き合成。
- 実時間同期とコース位置同期の切り替え。
- 自動位置合わせ失敗時の手動補正。
- 既存の骨格線・描画・速度調整・ABリピートとの連携。
- 補正行列・同期情報・描画情報のメタデータ保存と再読込。

既存のカメラ、録画、保存、再生、動画通信、タグ、比較表示の削除・仕様変更は禁止。原本動画と既存JSONを上書きしない。新機能は独立画面・専用処理として追加する案とし、既存画面への入口追加は将来の実装時に最小限とする。起動時画面・URLスキーム・録画処理を変更しない。

今回行う変更はこの文書の新規作成だけ。ビルド、実機インストール、アプリ起動、カメラ遷移、自動テストは未実施。実動画による精度・処理速度・端末温度の実測も未実施。

## 2. 結論と実現条件

条件付きで実装可能。既存の2動画選択・同期再生・骨格解析・描画保存・人物マスクを足場にできるが、位置合わせ、カメラ追跡、コース位置推定、Metalレンダラーは新規開発になる。リアルタイム解析を前提とせず、事前解析をキャッシュして再生時に合成する構成を推奨する。所要時間やfpsは未保証。

最大の制約はモーグルの立体地形と撮影位置差による視差。Homographyは平面間の射影変換であり、ほぼ同位置からの回転・ズームには適合しやすいが、撮影者の移動、近いコブと遠い境界の奥行き差、ローリングシャッター、電子手ぶれ補正による局所変形を単一行列で完全には補正できない。比較対象付近の背景ROIを優先し、「コース全域が常に完全一致する」とは約束しない。局所メッシュ変形や3D復元は初期範囲外とし、必要性が実証された場合のみ別途提案する。

白い雪面、反復するコブ、降雪・影・露出の差、ブラー、大きなズーム差、画角の非重複、雪煙・遮蔽は失敗要因。背景合わせが成功しても選手の進行位置が一致したとは限らず、空間合わせと時間同期を別々に扱う。

動画2本選択 → 解析区間・基準時刻指定 → 向き/時刻の正規化 → 人物除外マスク → 各動画内の背景追跡とキーフレーム化 → 動画間背景対応 → 同期マップ → 信頼度確認/手動補正 → Metalプレビュー → セッション保存。

## 5. 背景位置合わせ・追跡

1. preferredTransformを反映した表示向きの画素座標を基準にする。縮小解析の倍率、元解像度、ミラー、クロップを別々に保持。VFR動画はフレーム番号/fpsではなく実PTSを使用する。
2. 両動画の人物・観客等をマスクして特徴点から除外。背景除外用は余裕を持って膨張し、切り抜き表示用マスクとは分ける。小さい選手、雪煙、板・ストックの未検出はROIや手動除外で補う。骨格検出だけで人物領域全体を除外できるとは扱わない。
3. ORBを第一候補としてHamming距離で照合。ズーム差等で不十分ならSIFTとL2距離を使用。相互一致・近傍比・背景ROIを使って反復コブの誤対応を抑制し、RANSACでSUB→MAINのHomographyを推定。
4. 各動画内ではPyramidal Lucas–Kanadeで背景点を追跡し、前後整合・追跡誤差で点を選別。追跡点から毎回ロバストに変換を推定する。フロー単独で正確なカメラ運動を保証しない。
5. キーフレームへの再照合と動画間の直接照合で累積ドリフトを修正。カット、大ズーム、重複領域消失で追跡を区切る。解析は同期方式から独立した各動画の軌跡を保持し、実際の表示ペアでも検証する。
6. 時間的に平滑化する際は対応点/投影四隅を扱い、3×3行列要素の無条件線形補間を避ける。選手の軌跡を背景一致のために個別変形しない。

基準キーフレームをM0/S0、各時刻から基準への変換をGm(tM)/Gs(tS)、S0→M0をH0とすると、概念的には `H(tM,tS) = inverse(Gm(tM)) × H0 × Gs(tS)`。逆行列の存在・整合性を検査し、局所平面仮定と追跡誤差による限界を品質指標へ反映する。

品質はinlier数/比率、点の空間的分布、再投影誤差、重複領域、射影四隅の異常、時間的ジャンプで判定。4点は数学的最小条件であり、品質合格の根拠にはしない。閾値は解析解像度を明記し実動画で決める。低信頼区間は警告・半透明合成停止/手動切替を可能にし、古い行列を無期限適用しない。

手動補正は平行移動・回転・拡大縮小、4組以上の対応点（非共線で広く配置）、背景ROI、時刻アンカーを提供する案。自動結果への差分行列・適用区間・キーフレームを保存し、取消/やり直し・自動結果へ復帰できるようにする。

## 6. 同期方式・再生制御

### 実時間同期

録画の絶対日時ではなく、ユーザーが対応させた滑走開始等の基準からの等経過時間を意味する案。`tM = aM + u`、`tS = aS + u`。速度sは共通比較時間uの進行速度を変える。両動画の重なる有効区間だけ再生し、範囲外へ無断でクランプしない。これは既存リンク再生の考え方を利用できる。

### コース位置同期

同じコブ、境界目印、横断ゲート等を同じコース位置として対応付け、単調なアンカー列 `(tM_i, tS_i, coursePosition_i)` から区分線形時間マップを構成する。初期版はユーザーが複数の通過時刻を指定し、その後に背景座標へ投影した選手接地点とコース目印による自動候補を加える段階案。画面内の選手の高さだけではパン・ズームと進行を分離できない。

コース位置は初期には目印の順序/正規化進行度であり、実距離・実速度を意味しない。違うラインの選手を空間的に同一点へ引き寄せない。遮蔽・停止・区間欠落・不正なアンカー順序では無理な外挿をせず、区間分割または手動設定を要求する。完全自動化の精度は未検証。

コース同期ではSUBの時間進行率が変動するため、2つのAVPlayerへ同じrateを設定するだけでは不足。共通タイムラインと表示PTSでフレーム選択を管理し、非同期seek世代を分離する。AVPlayerItemVideoOutputによる取得と事前デコード方式を試作比較し、毎フレームseekする設計は避ける。フレーム欠落時は両動画の時刻整合を保って待機/低解像度化する。

同期切替は一時停止してMAINの現在位置を維持し、SUB時刻と変換を再評価する。ABはMAINの原動画PTSで保持し、各モードでSUB側対応区間を再計算する。速度表示は共通時間倍率とし、コース同期でSUBが時間変形されていることを表示する。初期音声はMAINのみを候補とし、非線形同期の音声処理は別途確定する。既存再生画面の音声仕様は変更しない。

## 7. 合成・骨格・描画

- MAINの背景を基準にSUBを射影し、全映像の半透明合成（不透明度調整）と、SUB選手マスクで切り抜いた合成を切り替える。人物マスクにも同じ射影を適用する。必要ならMAIN/SUBの役割をユーザーが交換する。
- CVPixelBufferからCVMetalTextureCache経由のテクスチャ化を検討。Metal側は逆写像でサンプリングし、同次座標除算と無効範囲を検査。重複領域外は透明/明示表示とし、引き伸ばしで埋めない。
- マスク輪郭・半透明のpremultiplied alpha、色域・HDR/SDR、YUV→RGB、回転、ミラー、アスペクト比を明示的に扱う。HDRは初期対応範囲を試作結果で決め、勝手に元動画を変換しない。
- 既存骨格は原動画時刻で検索し、Visionの座標原点を変換、動画の向きを正規化した後、SUBのみ背景と同じHで描画する。信頼度不足の関節は表示しない。古い推定を長時間表示しない。
- 既存描画は原動画ごとの時刻と座標を保ち読取専用で参照。新規描画はMAIN/SUB原動画に付くものと比較キャンバス固定のものを区別する。既存WJDrawingCanvasのbounds依存・余白・ズームの意味を確認して変換し、正規化点を画素座標と同一視しない。
- 射影後の見かけの角度は身体の真の角度ではない。既存解析値の意味を変更せず、表示変換後の骨格から採点値や身体計測値を生成しない。

合成動画の書き出しはユーザー要求で明示された必須項目ではないため初期版はプレビューとメタデータ保存を中心とする。将来追加する場合、同じタイムライン・Metal処理を利用したAVAssetReader/Writerまたはカスタムcompositorで別ファイルへ保存する。既存の並列比較書き出しを置換しない。

## 8. メタデータ仕様案

動画ペアには複数セッションがあり得るため、`Documents/OverlaySessions/<sessionUUID>/session.json` を候補とする。再生成可能な解析データはCachesの専用領域へ分離。原本脇の既存 `.wj.json` / `.tags.json` / `.pose.json` / `.drawing.json` と混在させない。

保存項目:

| 項目 | 内容 |
| --- | --- |
| 互換性 | schemaVersion、作成/更新日時、解析エンジン/OpenCV/モデル版、パラメータ |
| 原動画参照 | MAIN/SUBの動画ID、相対パス、サイズ、duration、解像度、preferredTransform、照合用fingerprint。絶対パスだけに依存しない |
| 同期 | モード、CMTimeのvalue/timescale（必要ならepoch）、基準時刻、コース位置アンカー列、比較有効区間、倍率、AB |
| 位置合わせ | 行列の方向SUB→MAIN、行優先9要素、左上原点の向き補正済み画素座標、解析/表示サイズと倍率、tM/tS、ROI、品質、失敗区間 |
| 補正 | 手動対応点、差分行列と合成順序、適用区間、キーフレーム、編集履歴の範囲 |
| 合成 | 不透明度、切り抜き方式、対象人物ID/選択領域、表示クロップ、ミラー、音声方針 |
| 描画・骨格 | sourceVideoID、原動画PTS/比較時間の別、座標系、表示区間、描画値。既存JSONの参照/スナップショットと元版の識別情報 |
| キャッシュ | マスク・追跡データの相対参照、失効キー、完了区間。全フレームの画像やマスクをJSONへ埋め込まない |

各行列に対応時刻と座標規約を持たせる。例として `p_MAIN ~ H_SUB_to_MAIN × p_SUB`、手動補正をMAIN座標で与えるなら `H_final = D_manual × H_auto` と定義し固定する。NaN/Infinity、不正な時刻、特異行列を保存/適用しない。

原子的書込とschema検証を行う。解析途中の取消・容量不足でも既存セッションを壊さない。原動画更新や同期アンカー変更で依存キャッシュを失効。動画が移動/削除されれば「参照動画なし」と表示し、同名別動画へ自動再接続しない。既存削除・通信処理は変更せず、比較セッションの明示削除と参照再指定を新機能内で扱う。比較セッションを既存動画通信へ自動添付する仕様は今回に含めない。

## 9. デグレ危険性と防止策

| 危険性 | 対策 |
| --- | --- |
| 比較画面のseek/AB/終端処理の競合 | 新画面でタイムライン管理を独立。既存リンク再生を変更しない |
| 録画や受信中のCPU/GPU/メモリ圧迫 | 録画系に解析を追加しない。解析キュー・同時数を制限し、非表示時の停止、取消、メモリ警告/thermal状態で負荷低減 |
| OpenCV導入によるC++/リンク/配布物肥大化 | Objective-C++ブリッジと必要モジュールに限定、依存版固定、アプリ/Watchターゲットへの影響を確認 |
| 背景追跡が選手を追って軌跡差を消す | 両動画の人物領域を除外、背景ROIとinlier分布を可視確認 |
| 反復コブへの誤対応を成功扱い | 再投影誤差だけでなく領域分布・時系列連続性・ユーザー目印を検証 |
| 座標系の相違で骨格/描画がずれる | 原動画/向き補正画素/解析画素/表示座標を分離し同じ変換を使用 |
| JSONや元動画破損、既存削除処理への干渉 | 新ストアに分離、原本と既存JSONを読取専用、原子的保存 |
| 戻る操作後の発熱・再生継続 | observer、display link、デコーダー、GPU参照、解析タスクを画面ライフサイクルで確実に解放 |

「既存仕様を変更しない」設計でも共有プロジェクトへのリンク追加等による影響は残る。デグレゼロを静的調査だけで保証することはできない。

## 10. 段階的実装計画と受入条件

### 段階0: 実素材による成立性確認

同位置/多少移動、明暗差、ズーム差、白い雪、反復コブ、遮蔽、異なるfps/向きの代表ペアで、静止フレームのORB/SIFT+RANSACを評価。ユーザーが比較したいコブ付近と遠景の誤差を分けて測る。手動対応点との差、inlier分布、重複領域、失敗検出率を記録する。閾値と対象端末・解像度・対応形式をここで決める。成立しない素材では完全一致を約束せず、手動ROI比較の実用性を確認する。

### 段階1: 独立画面と手動比較

2動画選択、実時間同期、手動位置補正、Metal半透明、速度/コマ送り/AB、セッション保存/再読込を実装。既存比較へ戻れること、既存録画・動画・JSONに変更がないこと、補正が再読込後一致することが受入条件。

### 段階2: 自動背景合わせ

人物除外、ORB/SIFT+RANSAC、LK追跡、再照合、信頼度、取消/再解析を実装。失敗素材を失敗として提示できること、解析完了/取消/再表示で負荷が残らないこと、実用的な背景一致を人間が確認できることが条件。解析時間、最大メモリ、再生fps、温度を対象実機で計測する。

### 段階3: 人物切り抜き・骨格・描画連携

Visionマスクを追加し、必要な場合のみCore MLを評価。2動画の骨格・既存描画をアダプター経由で表示、新比較描画を専用保存。細い板/ストック・雪煙での限界を明示し、半透明表示へ戻れること、元の描画JSON・解析値が変わらないことを確認。

### 段階4: コース位置同期

まず手動の通過アンカーで非線形同期、次に自動候補と追跡を追加。アンカー時点/中間/AB境界/同期切替/遮蔽区間を確認。画面上の選手位置だけに同期が依存しないこと、実時間モードと違う時間進行が識別できることを条件とする。

### 段階5: 完成確認

将来の実装時は依頼範囲のビルドエラー修正・再ビルド後、文脈上の対象実機へインストール・起動し、既存UIと利用可能な操作手段でカメラ画面遷移を試す。録画は自動開始しない。映像品質・背景一致・既存機能の操作確認は人間が担当する。大規模テスト環境やXCUITest撮影・不具合探索は構築/再開しない。限定的な時刻マップ・行列・メタデータの検証は実装内容に応じて行うが、既存の作成途中テストは無断実行しない。

## 11. 未確定事項

実装着手時に、対象実機、代表動画、許容する背景誤差、解析待ち時間、プレビュー解像度/fps、コース目印の指定方法、人物切り抜きの必要品質、音声、書き出し要否を確定する。現段階でこれらを実測済み・実装済みとは扱わない。既存構成からは段階1〜2を最初の実装範囲にすることを推奨するが、ユーザーの実装指示を待つ。
